## Intent

**Problem:** There is no way to run the whole system end to end. `infra/docker-compose.yml`, its override and `infra/nginx/nginx.conf` are empty (0 bytes), so `make up` starts nothing. The 7.4 GB laptop cannot run Fabric and the app together. Daraja needs a public HTTPS callback.

**Approach:** Option A, chosen by the user (2026-10-21), on AWS with $100 student credits. One EC2 VM runs the Fabric testnet (existing scripts) plus an app compose file: Postgres, Redis, ml-engine, gateway, PWA and Caddy. Caddy gets an automatic Let's Encrypt certificate for `<ip>.sslip.io`, serves the PWA and `/api/*` on one origin, and gives Daraja its HTTPS callbacks. The gateway joins the `salesmesh_fabric` Docker network and reaches `peer0.merchant` over mTLS without the peer being exposed. Secrets live only in `.env` files on the VM, generated by a script.

**Decisions (2026-10-21):** A regular AWS account with $100 credits, shared with the user's other projects. So the runbook covers credit management: every SalesMesh resource is tagged `Project=salesmesh` (cost allocation tag), an AWS Budget for that tag alerts at 50/80/100 %, the VM is stopped whenever no demo is running (only the EBS volume and Elastic IP bill while it is stopped), and a teardown section deletes everything the runbook created.

## Boundaries & Constraints

**Always:** Config comes from env. The Fabric org crypto is mounted read-only from `blockchain/network/organizations` and never copied. Every container has a `mem_limit`. Only ports 80 and 443 (plus 22, restricted to the user's IP) are open in the security group. The scripts are idempotent and safe to re-run. All existing make targets keep working.

**Never:** No secrets or keys in git. No publishing of 7051, 5432, 6379 or 8000 to the internet. No Terraform/IaC (manual console steps in the runbook). No changes to the gateway or PWA code beyond what deployment needs. No commits to dev or main.

| Fresh VM | `bootstrap_vm.sh` on Ubuntu 24.04 | Docker + compose plugin, 4 GB swap, user in docker group | Re-run is a no-op |

| Callback | Daraja POST `https://<host>/api/v1/mpesa/callback/<token>` | Caddy → gateway, 200 | Wrong token → gateway's existing 404 |
| Fabric off | `FABRIC_ENABLED=false` | The app runs without the `salesmesh_fabric` network | Compose must not fail when that network is absent (separate overlay file) |

## Design Notes

AWS sizing: t3.medium (2 vCPU, 4 GB, x86 so there is no arm64 image risk) ≈ $0.042/h. Add a 30 GB gp3 volume and a public IPv4 ≈ $0.05/h in total. Stopped when idle, that is ~2000 running hours on $100. The RAM estimate is ~2.7 GB used, with 4 GB swap as headroom. t3.large (8 GB, ≈ $0.083/h) is the fallback if the OOM killer shows up.
